## Ticks

The lowest-level unit of time is the **tick**. In Margrete, the tick resolution is 1920, meaning one whole note (1/1) spans exactly 1920 ticks. In a 4/4 chart that gives:

<div className="flex gap-2">

    <div className="flex-1">

    | Duration                              | Ticks |
    | ------------------------------------- | ----- |
    | Whole note (1/1)                      | 1920  |
    | Half note (1/2)                       | 960   |
    | Quarter note (1/4)                    | 480   |
    | Eighth note (1/8)                     | 240   |
    | Sixteenth note (1/16)                 | 120   |

    </div>

    <ImageZoom src={NoteTickListImage} alt="Note tick list" width="205" />
</div>

```python
from margrete_rpc.chart.time import TICK_RESOLUTION  # 1920

Tap(t=TICK_RESOLUTION * (1 / 4), x=0, w=4) # Place a tap on bar=0 beat=1 (tick=480)
```

Ticks are accepted everywhere a time argument (`t=`) appears, so if you already known the number, just use it directly.

## Positions

### Tick conversion

Tick math gets unwieldy for anything beyond trivial placements. 

`Position(bar, beat, offset)` gives you the same moment in musical terms. All three fields are **zero-based**, and `offset` is the remaining ticks within the beat.

```
bar 0, beat 0 ──── bar 0, beat 1 ──── bar 0, beat 2 ──── bar 0, beat 3
tick 0             tick 480            tick 960            tick 1440
```

Convert freely with `t2p` (tick → position) and `p2t` (position → tick):

```python
from margrete_rpc.chart.time import Position, t2p, p2t

# By default, t2p and p2t assume you are 4/4 when no time signature context.

pos = t2p(1920) # Where is tick 1920?
print(pos.bar, pos.beat, pos.offset) # bar 1, beat 0, offset 0

# Turn (bar 2, beat 3) back into a tick
tick = p2t(2, 3)   # 2 * 1920 + 3 * 480 = 5280
```

### Tuple shorthand

Typing `t=p2t(2, 1, 0)` everywhere is verbose. Any function that takes a time argument also accepts a plain **tuple** that the Python client expands for you:

| Tuple                 | Equivalent position        |
| --------------------- | -------------------------- |
| `(bar,)`              | `bar, beat=0, offset=0`    |
| `(bar, beat)`         | `bar, beat, offset=0`      |
| `(bar, beat, offset)` | fully specified             |

```python
Tap(t=(2,), x=0, w=4)           # bar 2, beat 0
Tap(t=(2, 1), x=0, w=4)         # bar 2, beat 1
Tap(t=(2, 1, 240), x=0, w=4)    # bar 2, beat 1, halfway through the beat
```

This is the most readable way to place notes when you are thinking in bars and beats.

### Inside a transaction

When the chart has time-signature changes (e.g. a section switches from 4/4 to 3/4), a given bar number maps to a *different* tick count depending on where it falls. Inside a `with m.open_edit()` block, the chart's beat events are active automatically, so tuple positions always resolve correctly without any extra work:

```python
with m.open_edit() as tx:
    # The chart might be 4/4 for the first 8 bars and then switch to 3/4.
    # This tuple resolves to the right tick for whatever signature bar 10 is in.
    tx.chart.notes.append(Tap(t=(10, 0), x=0, w=4))
```

If you need to resolve a position **outside** a transaction, pass the beat events explicitly:

```python
from margrete_rpc.chart.time import p2t

tick = p2t(10, 0, 0, beat_events=chart.events.beat)
```

Or skip the conversion entirely and use a raw tick.

## Interval

Positions tell you *where* a note starts. For anything that has a **length** — hold notes, long notes — you need a duration.

`d2t(numerator, denominator)` converts a note fraction to ticks:

```python
from margrete_rpc.chart.time import Interval, d2t, t2d

quarter = d2t(1, 4)    # 480 ticks  (one quarter note)
eighth  = d2t(1, 8)    # 240 ticks
dotted  = d2t(3, 4)    # 1440 ticks (three quarter notes)

# Going the other way
interval = t2d(480)    # Interval(numerator=1, denominator=4)
```

The same tuple shorthand works for duration arguments too:

```python
# Snap a note's start to the nearest eighth note
note.align((1, 8))

# AirCrush with a dotted-quarter gap between segments
AirCrush(t=0, x=0, w=4, h=4, gap=(3, 4), ...)
```

> `d2t` raises `ValueError` if the fraction doesn't land exactly on a whole tick (this can happen with very large denominators like `1/2048`).

## Working with time signatures

If you need to inspect or iterate over the chart's time signatures, they live at `tx.chart.events.beat` as a list of `BeatEvent` objects. Each event marks where a new signature takes effect (by zero-based bar number):

```python
with m.open_edit() as tx:
    for event in tx.chart.events.beat:
        print(f"Bar {event.bar}: {event.beats_per_bar}/{event.beat_unit}")
    # Example output:
    #   Bar 0: 4/4
    #   Bar 16: 3/4
```

For manual conversions that account for multiple time-signature changes, build a `TimeCalculator`:

```python
from margrete_rpc.chart.time import TimeCalculator

calc = TimeCalculator(tx.chart.events.beat)
pos  = calc.t2p(3840)      # same as t2p but signature-aware
tick = calc.p2t(1, 2, 0)   # same as p2t but signature-aware
```

In practice you only need `TimeCalculator` when writing utility code that runs outside a transaction context. Inside a transaction the tuple shorthand handles this for you automatically.
