## Ticks

The lowest-level unit of time is the **tick**. In Margrete, the tick resolution is 1920, meaning one whole note (1/1) spans exactly 1920 ticks. In a 4/4 chart that gives:

<div className="flex gap-2">

    <div className="flex-1">

    | Duration                              | Ticks |
    | ------------------------------------- | ----- |
    | Whole note (1/1)                      | 1920  |
    | Half note (1/2)                       | 960   |
    | Quarter note (1/4)                    | 480   |
    | Eighth note (1/8)                     | 240   |
    | Sixteenth note (1/16)                 | 120   |

    </div>

    <ImageZoom src={NoteTickListImage} alt="Note tick list" width="205" />
</div>

```python
from margrete_rpc.chart.time import TICK_RESOLUTION  # 1920

tap = Tap(t=TICK_RESOLUTION*(1/4), x=0, w=4) # (bar 0, beat 1) at 4/4
print(tap.t) # 480
```

Ticks are accepted everywhere a time argument (`t=`) appears, so if you already know the number, just use it directly.

## Positions

Tick math gets unwieldy quickly. To be more intuitive, `Position(bar, beat, offset)` lets you address the same moment in musical terms.

```
For 4/4:

bar 0, beat 0 ──── bar 0, beat 1 ──── bar 0, beat 2 ──── bar 0, beat 3
tick 0             tick 480           tick 960           tick 1440
```

Convert freely with `tick_to_pos` and `pos_to_tick`:

```python
from margrete_rpc.chart.events import BeatEvent
from margrete_rpc.chart.time import Position, tick_to_pos, pos_to_tick

pos = tick_to_pos(1920, beat_events=[BeatEvent(0, 4, 4)]) # 1920 tick at 4/4
print(pos) # bar 1, beat 0, offset 0

# without beat_events parameter, 4/4 is assumed
tick = pos_to_tick(2, 3)
print(tick) # 2 * 1920 + 3 * 480 = 5280
```

All three fields are **zero-based**, and `offset` is the remaining ticks within the beat.

### Automatic resolution

However, typing `t=pos_to_tick(2, 1, 0)` everywhere is still verbose. 

To simplify that, any function that takes a time argument (`t=`) now also accepts a plain `Position` **tuple**.

```python
Tap(t=(2,), x=0, w=4)           # bar 2, beat 0
Tap(t=(2, 1), x=0, w=4)         # bar 2, beat 1
Tap(t=(2, 1, 240), x=0, w=4)    # bar 2, beat 1, halfway through the beat
```

Inside a `with m.open_edit()` block, the chart's beat events are used automatically, so tuple positions always resolve to tick correctly without any extra work.

```python
from margrete_rpc.chart.events import BeatEvent

with m.open_edit(snapshot=False) as tx:
    tx.chart.events.beat.append(BeatEvent(0, 3, 4)) # 3/4
    tx.chart.notes.append(Tap(t=(10, 0), x=0, w=4))
```

It can also handle the case that when the chart has time-signature changes (e.g. a section switches from 4/4 to 3/4).

By default, 4/4 time signature is assumed when outsiding the transaction. If you need to resolve a position **outside** a transaction in other cases, pass the beat events explicitly:

```python
from margrete_rpc.chart.events import BeatEvent
from margrete_rpc.chart.time import pos_to_tick

beats = [BeatEvent(0, 3, 4)] # 3/4
tick = pos_to_tick(10, 0, 0, beat_events=beats)
```

## Division

Positions tell you *where* a note starts. For anything that has a **length** — hold notes, long notes — you also need a duration. `div_to_tick(numerator, denominator)` converts a note fraction to ticks:

```python
from margrete_rpc.chart.time import Division, div_to_tick, tick_to_div

quarter = div_to_tick(1, 4)    # 480 ticks  (one quarter note)
eighth  = div_to_tick(1, 8)    # 240 ticks
dotted  = div_to_tick(3, 4)    # 1440 ticks (three quarter notes)

# Going the other way
division = tick_to_div(480)    # Division(numerator=1, denominator=4)
```

The same tuple shorthand works for duration arguments too:

```python
# Snap a note's start to the nearest eighth note
note.align((1, 8))

# AirCrush with a dotted-quarter gap between segments
AirCrush(t=0, x=0, w=4, h=4, gap=(3, 4), ...)
```

<Callout type="warn">
    `div_to_tick` raises `ValueError` if the fraction doesn't land exactly on a whole tick.
    This can happen with very large denominators like `1/2048` (smaller than `1/1920`).
</Callout>

## Working with time signatures

The chart's time signatures live at `tx.chart.events.beat` as a list of `BeatEvent` objects.

```python
from margrete_rpc.chart.events import BeatEvent

with m.open_edit(snapshot=False) as tx:
    beats = tx.chart.events.beat

    beats.append(BeatEvent(0, 4, 4))
    beats.append(BeatEvent(16, 3, 4))

    for event in beats:
        print(f"Bar {event.bar}: {event.beats_per_bar}/{event.beat_unit}")

    # Example output:
    #   Bar 0: 4/4
    #   Bar 16: 3/4
```

For manual conversions that account for multiple time-signature changes, build a `TimeCalculator`:

```python
from margrete_rpc.chart.time import TimeCalculator

calc = TimeCalculator(tx.chart.events.beat)
pos  = calc.tick_to_pos(3840)      # same as tick_to_pos but signature-aware
tick = calc.pos_to_tick(1, 2, 0)   # same as pos_to_tick but signature-aware
```

In practice you only need `TimeCalculator` when writing utility code that runs outside a transaction context. Inside a transaction the tuple shorthand handles this for you automatically.
