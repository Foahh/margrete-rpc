title: Edit Transactions
description: Atomic chart edits with open_edit — reading the chart, modifying notes and events, and apply modes.
---

An **edit transaction** is the core of the Margrete RPC workflow. It snapshots the current chart, lets you mutate it freely, and on clean exit sends only the changed notes to Margrete as a single undoable edit.

## Basic pattern

```python
from margrete_rpc import Margrete

m = Margrete()

with m.open_edit("my edit name") as tx:
    # tx.chart holds the loaded chart
    # mutate tx.chart.notes and tx.chart.events here
    ...
# on clean exit, changes are applied to Margrete
# if the block raises, nothing is sent
```

The name passed to `open_edit` appears in Margrete's undo history.

## Reading the chart

`tx.chart` is a `Chart` object with two attributes:

- **`tx.chart.notes`** — `list[ChartNote]`, either typed `Note` objects or `RawNote` trees
- **`tx.chart.events`** — `ChartEvents` with `.bpm`, `.beat`, `.til`, and `.note_speed` lists

```python
with m.open_edit("inspect") as tx:
    print(f"{len(tx.chart.notes)} notes")
    for event in tx.chart.events.bpm:
        print(f"BPM {event.bpm} at tick {event.t}")
```

## Modifying notes

Append, remove, or mutate items in `tx.chart.notes`. The diff is computed on exit.

```python
from margrete_rpc.chart.notes import Tap, Flick

with m.open_edit("rewrite notes") as tx:
    # add a note
    tx.chart.notes.append(Tap(t=(0, 0, 0), x=4, w=4))

    # remove notes by filtering
    tx.chart.notes = [n for n in tx.chart.notes if n.x >= 4]

    # mutate in place
    for note in tx.chart.notes:
        note.shift(x=2)
```

## Apply modes

`open_edit` supports three apply strategies:

| Mode | Parameter | Behaviour |
|---|---|---|
| **Diff** (default) | `scan=True` | Snapshots on enter; sends only added/changed/deleted notes on exit. |
| **No diff** | `scan=False` | Sends all notes in the final chart as upserts. No server ids allowed. |
| **Replace all** | `replace_all=True` | Strips all ids, sends every note as a fresh upsert, replaces the whole chart. |

```python
# diff mode (default) — only changes are sent
with m.open_edit("nudge") as tx:
    for note in tx.chart.notes:
        note.shift(x=1)

# replace-all mode — good for full rewrites
with m.open_edit("overwrite", replace_all=True) as tx:
    tx.chart.notes = build_notes()

# no-diff, raw mode — efficient for streaming or generated charts
with m.open_edit("stream frame", scan=False, raw=True, replace_all=True) as tx:
    tx.chart.notes = raw_notes_for_frame()
```

## Implicit tick resolution

Inside a `with m.open_edit()` block, the chart's beat events are installed as an active context. This means note constructors accept `t=(bar, beat, offset)` position tuples and resolve them automatically — you don't need to pass beat events explicitly.

```python
with m.open_edit("place notes") as tx:
    # (bar=2, beat=0, offset=0) resolves to an absolute tick
    tx.chart.notes.append(Tap(t=(2, 0, 0), x=0, w=4))
    # single-element tuple: (bar=4,)
    tx.chart.notes.append(Tap(t=(4,), x=0, w=4))
```

Outside a transaction, pass `beat_events=` explicitly or use raw ticks.

## Event scan parameters

When a chart has many timeline-speed (TIL) events, you can control how far the plugin scans for them:

```python
with m.open_edit(
    "edit",
    event_scan_extra_tick=1920 * 4,   # scan 4 beats past the last note
    event_scan_note_til_only=True,     # only scan ticks that carry notes
) as tx:
    ...
```

These parameters trade completeness for request latency. The defaults work for most charts.

## Undo and redo

Each applied edit appears as one item in Margrete's undo stack. You can also trigger undo/redo programmatically:

```python
m.undo()  # True if something was undone
m.redo()  # True if something was redone
```

<Callout type="warn">
  Undoing a transaction that **deleted** notes can re-create them in a duplicated state — this is a plugin limitation. Prefer edits that add or modify rather than relying on undo to reverse deletions.
</Callout>

## Current playhead tick

```python
tick = m.current_tick()  # playhead position in the editor
```

This is also available on the transaction as `tx.current_tick` for the snapshot captured when the edit opened.
