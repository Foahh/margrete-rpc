# AGENTS.md

Margrete RPC connects a Python client to a Rust plugin running inside Margrete over Windows named pipes and protobuf.

## Where to look

- Python client: `python/margrete_rpc/`; tests: `python/tests/`; tooling: `pyproject.toml`.
- Rust server: `plugin/src/`; build and dependencies: `plugin/Cargo.toml` and `plugin/build.rs`.
- RPC contract: `proto/margrete/rpc/messages.proto` and `proto/API_VERSION`. For protocol changes, review compatibility and the corresponding Rust handlers and Python client behavior together.
- Documentation: `website/` is a Fumadocs site. For website work, use the scripts in `website/package.json`.

## Source and generated files

- Edit protobuf definitions in `proto/`. Python stubs in `python/margrete_rpc/_proto/` are gitignored and generated by the hatch build hook or `uv run --extra dev python scripts/generate_proto.py`. Rust protobuf code is generated by `plugin/build.rs`.
- Edit Python docstrings or `website/scripts/generate-docs.mjs` for API-reference changes. The generator replaces `website/content/docs/reference/`.
- Use `plugin/margrete/` as the ABI header reference only; do not compile this submodule.

## Completion and verification

Complete the requested behavior, verify it, and fix failures caused by the change. Proceed with local edits, builds, and checks within that scope without repeated confirmation. Ask when a missing decision materially changes the intended behavior or scope.

Choose checks for the affected behavior and component; the commands below are available checks, not a mandatory sequence. Prose-only edits usually need a diff and accuracy review. Protocol changes need coverage on both sides. Report the result, checks run, and unresolved blockers.

| Component / working directory | Checks |
| --- | --- |
| Python / repository root | `uv run --extra dev pytest [test-path]`; `uv run --extra dev pyright`; `uv run --extra dev ruff check python/`; `uv run --extra dev ruff format --check python/` |
| Rust / `plugin/` | `cargo fmt --check`; `cargo clippy --all-targets -- -D warnings`; `cargo test`; `cargo build --release` |
| Website / `website/` | `bun run lint`; `bun run fmt:check`; `bun run types:check`; `bun run build` |

- Python: use `uv`; compatibility and tool settings live in `pyproject.toml`. Omit `[test-path]` for the full suite. Format changed files with `uv run --extra dev ruff format <paths>`.
- Rust: use Windows, stable Rust, and the MSVC target (`x86_64-pc-windows-msvc`), with `rustfmt`, `clippy`, and `protoc` available. Apply formatting with `cargo fmt`.
- API-reference regeneration: run `bun run build:docs` in `website/` with the client dependencies available to Python. The extraction script invokes `pip` and `fumapy-generate`.

## Packaging and conventions

- From the repository root, `.\build.ps1 -Test` runs Rust tests and builds `plugin/target/release/margrete_rpc.dll`.
- For local packaging, `.\build.ps1 -Publish` replaces `publish/` with the DLL, INI, and installation README. Release checks and publication are defined in `.github/workflows/release.yml`.
- `.\format.ps1 -Check` checks Rust formatting and Python formatting/lint; `.\format.ps1` applies formatting and Python lint fixes.
- Use conventional commit prefixes such as `feat:`, `fix:`, `refactor:`, `chore:`, and `docs:`.
- Put agent temporary files in `.tmp/codex/<task-id>/` or a unique system temporary directory.
- Reserve `E:\.cache` for tool-managed dependency caches; leave existing cache contents to their managing tools unless the user requests cleanup.
